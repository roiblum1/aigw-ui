# 0.19.0 (2026-10-15)

A model's standard budget: every tenant may use the model up to it, each
with a count of its own, through one rule on the gateway in place of a rule
per tenant; a tenant's own quota adds to it as an exception. Step 5b of the
[design](../design/capacity-prices-wallets.md#identity-and-quota-rules).

Database: migration 022 adds a model's standard and a change of it that
waits for its day.

## Upgrading

Nothing changes on the gateways, and no count is lost: a model keeps its
rule per tenant until an operator gives it a standard, and that starts at
the next 00:00 UTC, when every count starts anew.

A standard needs every tenant on tokens (0.18): the gateway reads the tenant
from the token, and a request with an API key carries none. It cannot be
set before the last API key is revoked, and while a model has one, no API
key can be created and no tenant that still has one enabled.

**Fixed:** a model that got its first prices had an unset best-effort limit
turned into a limit of 1 credit, so a tenant past its budget was refused
after its first best-effort request. Since 0.11.0. Look at the best-effort
limit of every priced model that has best-effort on: one of 1 credit that
nobody chose came from this.

## What changed

- **Standard budget**, on the Models page: an amount per minute, hour or
  day for every tenant. One `Distinct` rule on `x-aigw-tenant` gives every
  tenant a bucket of its own (lab check A1). A tenant's quota on the model
  becomes an `Exact` rule on `x-aigw-tenant`, which adds to the standard: a
  request passes while either has room, so no tenant is held below it. To
  give a tenant less, lower the standard and give the others exceptions; the
  smallest amount closes the model to everyone without one.
- **It starts at the next 00:00 UTC**, as prices do, and a waiting change
  can be cancelled. Prices convert it once, as they convert quotas.
- **The rule count** of each model's QuotaPolicy is on the Models page,
  with what a rule per tenant would take.
- **Counters:** a tenant on the standard is counted under its slug, an
  exception under its rule (lab check A3); the Usage page, the best-effort
  mover, usage reset, the hourly history and the tenants' own page read
  them. A tenant's page lists the models it uses on the standard alone.
- **Self-test:** "A client cannot choose its tenant by the tenant header"
  sends the tenant's token with another slug in `x-aigw-tenant`; it passes
  when the request is counted for the token's tenant and nothing for the
  slug sent. Under a standard, "a request over the quota is refused" is
  skipped: no quota lowers the standard.
- **API:** `PUT /models/{id}/standard`, `DELETE /models/{id}/standard/pending`;
  a model has `standard`, `standard_next`, `rules`, `rules_per_tenant` and
  `standard_held`. `POST /tenants/{id}/keys` with `"kind": "key"` and
  enabling a tenant with API keys are refused (409) while a model has a
  standard.

## Tested

- **Against what the lab's gateway did** (lab check A, AI Gateway 1.2.0):
  the rules the hub renders are the ones checks A1, A2 and A4 ran, and the
  counter names `render.Counters` computes are the Redis keys check A3 found,
  character for character, for a tenant on the standard, an exception and
  the default bucket.
- **Units:** the policy with a standard (the `Distinct` rule first, the
  exceptions by name, both shadow on the best-effort route), the revision
  changing with it, a policy without quotas still rendered, nothing changed
  without a standard; the counter of a slug a client made up; the rule
  counts.
- **Store, on Postgres:** a standard waits for its day, starts, is removed
  and a waiting change cancelled; the gateway gets it only with tokens only;
  a counter for every enabled tenant, the tenant with a quota on its own;
  prices convert a standard and leave an unset best-effort limit and
  standard unset.
- **The real CRDs** (`hack/test-apiserver.sh`): the `Distinct` rule and the
  exception accepted.
- **A local hub:** refused a standard while a tenant had an API key (409),
  took it with tokens only (204), refused an API key then (409), started it
  on its day, and rendered the `Distinct` rule and an exception; the Models
  page showed the standard and 2 rules, the dialog, and tenant b on the
  standard alone, at 1440 and 390 px, with no console errors.

## Not tested

- **On a real gateway with the hub's own sync**: the lab login expired. The

- **Many tenants**: one rule per model was the point, but a standard with
  hundreds of tenants, and their counters on the Usage page, were not tried.
- **The best-effort mover under a standard** on a real gateway.
