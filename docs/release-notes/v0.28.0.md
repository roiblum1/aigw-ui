# 0.28.0 (2026-10-17)

The image carries the documentation of the projects the platform is built
on: Envoy AI Gateway, Envoy Gateway, KServe, vLLM and llm-d. The Docs page
shows it under **Upstream** and searches it, where there is no internet. A
weekly workflow moves it to every project's newest release, as the market
snapshot's does for prices. And CI no longer tests a merge twice.

No database change.

## Upgrading

- Nothing to do. The image is about 57 MB larger. Building it needs access
  to GitHub (`codeload.github.com`), as building it needed the internet
  before.

## Added

- **Upstream documentation.** `docs/upstream/projects.json` pins each
  project's repository, docs folders and version: Envoy AI Gateway v1.2.0,
  Envoy Gateway v1.9.2, KServe 0.20 (its website's newest version), vLLM
  v0.31.0 and llm-d v0.10.0. `cmd/upstream-docs fetch`, a stage of the
  image build, downloads them from GitHub and keeps the Markdown pages, the
  images they show and the license. It turns into plain Markdown what only
  each site generator reads: Hugo shortcodes (Envoy Gateway), Docusaurus
  admonitions, tabs, code blocks and API fields (Envoy AI Gateway, KServe),
  MkDocs admonitions and tabs (vLLM); and it points links between pages at
  the hub, other links at the project's site or GitHub, and images at the
  hub. 772 pages and 202 images, about 57 MB.
- **The Docs page.** **Upstream** lists each project with its version, its
  pages in folders that open at the current page. A line above an upstream
  page names the project, its version, the repository it comes from and
  its license. **Filter titles** narrows the list, ours and upstream;
  **Enter** searches the text of every document (`GET
  /api/v1/docs/search?q=`), the ones with it in the title first.
- **Served without a token** (`/upstream-docs/…`): it is public
  documentation, like the UI's own files. Every file goes with a policy
  under which nothing runs (`default-src 'none'; sandbox`), an SVG opened
  on its own included, and the page shows an upstream page's HTML only
  after DOMPurify cleaned it.
- **Weekly.** The workflow `upstream-docs` runs `cmd/upstream-docs latest`
  every Monday: every project to its newest release (KServe: its website's
  newest commit and version). It fetches the docs to check they are still
  where the converter looks, and opens or updates the pull request
  "Upstream docs YYYY-MM-DD" with the new versions and what the image will
  carry.

## Changed

- **CI tests a merge once.** A pull request's run notes the tree it tested
  as the status `ci/tested-tree` on its head. After the merge, a new job
  `seen` compares it with the merge commit's tree; when they are the same,
  the tests and AIPerf are skipped and the image is built at once, about
  nine minutes sooner. A merge after `main` moved, a tag, and a pull request
  from a fork are tested again.
