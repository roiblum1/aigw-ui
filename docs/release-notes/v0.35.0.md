# 0.35.0 (not released yet)

The hub deploys the models too. A new page, Deployments, reads and writes
the values files of the Argo CD platform (argocd-day2-platform's layout:
`operators/<model>/` and `sites/<site>/<env>/mces/<mce>/<cluster>/<model>/`),
and Argo CD deploys them with one chart for every model, `model-deployer`
(in the doomsday-stack repository).

Database: no migration. The repository is the source of truth; the hub
keeps nothing of it.

## In short

**What was missing.** A model reached the hub only after someone deployed
it by hand: its own chart per model (glm53, qwen38, the judge), its values
in git, an Argo CD app, and then discovery found it. Running the same model
on another cluster in another shape (B300 with 8 data-parallel ranks, H200
with tensor parallel 8, two H200 nodes over RoCE) meant a values file
written by hand for each, with every flag repeated.

**What 0.35.0 does.**

1. **One chart for every model.** `model-deployer` is the whole stack the
   per-model charts deployed (node preparation, local PVs, per-node S3 pull
   jobs, the LMCache engine, the LLMInferenceService and its scheduler) plus
   the fleet side (the peer route, the health route, the request classes,
   flow control). glm53, qwen38 and the judge point at it; their recipes
   render what their old charts rendered, with three request classes and
   the capacity annotation added.
2. **A recipe per model, a shape per cluster.** The model's recipe
   (`operators/<model>/values.yaml`) holds what is the model's: weights,
   images, its vLLM and LMCache flags. Each cluster's own file holds its
   shape: data parallel over ports, tensor parallel, or a replica over two
   nodes on RoCE (KServe's LeaderWorkerSet), its GPUs and its own flags.
3. **The page.** Deploy a model on a cluster, change a cluster's values,
   remove a model from a cluster, edit a recipe, add a model copied from
   another. Each save is one commit; the hub writes only what differs from
   the layers below, and keeps the comments of the files it changes. Each
   deployment shows Argo CD's sync and health and how many of its replicas
   are ready.

## Upgrading

- The image has `git` and `ssh` (the hub commits with them). Nothing to do
  for a hub that does not use the page.
- To turn the page on: `gitops.repo`, `gitops.branch`, `gitops.dir`
  (`gitops/app-of-apps` for the platform's layout), and a Secret that may
  push (`gitops.existingSecret`, `gitops.auth: token` or `ssh`). See the
  deployment guide, "Before the first model deployment".
- Optional: `gitops.argocdNamespace` and the read-only Role in Argo CD's
  namespace, for each deployment's sync and health. The pod then mounts
  its account's token (it did not before).
- The doomsday-stack repository: merge `model-deployer` and point the model
  apps at the chart (their `operators/<model>/<model>.yaml`). The first sync
  of each model app changes its pods once where its recipe differs from its
  old chart (the request classes are new; the node-prep script's comments
  changed, which rolls the node-prep pods).

## Fixed during the live check

- A recipe edit of a quoted value (`"4"`) re-encoded the whole file
  (21-line diff for one value): quoted values are now changed in place too,
  and files the hub creates use the same list indentation as its patches.
- The page said "no Application yet" for clusters another Argo CD keeps, and
  "git is at …" on every app whenever any file changed: now "not in this
  Argo CD" and "compared at <commit>". Its buttons no longer leave the
  screen.
- model-deployer: the health route writes the backend defaults the API
  server adds (Argo CD showed it OutOfSync forever); the download Job
  prefers the model's node (its ReadWriteOnce PVC is mounted there).

## Tested

2026-10-24, sandbox hub (OpenShift 4.20, OpenShift GitOps 1.18.6) and the lab
(OpenShift 4.22, KServe 0.21, Envoy Gateway 1.9.2, AI Gateway 1.2.0 patched),
doomsday-stack `main` over a write deploy key (SSH), `gitops.dir`
`gitops/app-of-apps`, `gitops.argocdNamespace` `openshift-gitops`.

- **Argo CD:** the lab registered for the project `aigw-ui-models`
  (AppProject: only the chart's kinds, not in the platform's or gateway's
  namespaces), the lab's ApplicationSet `popai-lab`. Registering the lab put
  the shared application controller over its 2 GiB limit: OOMKilled 18 s
  after each start, 17 restarts, every app on that Argo CD stalled. Raised to
  4 GiB in the ArgoCD resource; no restart since.
- **qwen-tiny moved under Argo CD:** its spec first moved to the chart's by
  one patch (one rolling restart, weights from a Ceph PVC filled in 7 s);
  `popai-lab-qwen-tiny-deploy` then adopted all 10 objects, Synced and
  Healthy, without a restart; its hand-installed Helm release's records were
  removed.
- **Check 35, through the hub's API:** a new model `e2e-r035-small` copied
  from qwen-tiny and deployed on the lab in one commit (2.1 s, three files,
  author `aigw-ui`); the Application made in 26 s; Synced and Healthy at
  432 s (about 6 minutes of it the controller's crash loop); the download
  Job ran first (wave −1); the LLMInferenceService Ready 131 s later;
  discovered by the hub 94 s later (source `discovered`), 688 s from the
  commit. Scaled to 2: the lab's file held only `replicas: 2`; 2 of 2 ready
  in 233 s. The same save on the old version: 409. The recipe edit: one
  commit (the 21-line diff fixed above). Removal: one commit; the
  Application gone at 337 s (Argo CD's 3-minute refresh, no webhook), the
  model and its namespace deleted with it (`namespaceCreate`), off the page.
- **The page** on the sandbox hub in Chromium: both tables, Argo CD's status
  and the ready count of qwen-tiny, no page errors.
- `go test -race ./...` (Postgres 17, Redis 7) incl. `internal/gitops`
  against real bare repositories and `TestDeploymentsInGit`; vet, dupl,
  gofmt, `hack/check-chart.sh` (two new variants), `hack/check-release-note.sh`;
  web tests (23), tsc, build; the image built locally (git 2.52, OpenSSH
  9.9) and HTTPS git under a UID without a passwd entry. The chart: lint and
  render of every recipe, compared with the old charts (see the doomsday-stack
  PR #5).

Not run: any GPU shape (B300 DP8, H200 TP8, 2 × H200 RoCE DP8 TP2 EP16),
LMCache, node preparation and pull jobs, the real argocd-day2-platform, a
git webhook to Argo CD, the first sync of glm53/qwen38/judge on the new chart.
