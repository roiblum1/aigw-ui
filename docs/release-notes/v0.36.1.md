# 0.36.1 (not released yet)

People on Windows can set up Claude Code and Oh My Pi from the hub, and
every machine set up from the hub keeps itself up to date. The installer
and `aigw-token` were `sh` scripts. Claude Code on Windows runs its
`apiKeyHelper` with `cmd.exe` and Oh My Pi runs commands with its own shell,
so neither could run them, and on Windows the setup failed (one report said
"ELF"). Windows now has its own installer and `aigw-token` in PowerShell.
`aigw-token` also runs the hub's installer again by itself when the hub
serves other client files, so a change to the clients reaches people with
nothing for them to do.

Database: no migration.

## Upgrading

Nothing to do on the hub. People on Windows run the new line from
`/my-usage` in PowerShell:

```powershell
iex "& { $(irm https://<the hub>/clients/install.ps1) } https://<the hub>"
```

Every machine has to run the installer once more, as `/my-usage` shows
it, before it follows the hub: a setup from before 0.36.1 kept no version.

## Changed

- `install.sh` stops in Git Bash, MSYS2 or Cygwin and gives the PowerShell
  line. In WSL it leaves out Windows' own programs, which WSL puts on the
  `PATH` under `/mnt/<drive>/`: a Windows `claude` or `omp` keeps its
  settings in the Windows home, which this does not set up, and fails when
  run from Linux. It names them and gives the PowerShell line.
  `AIGW_WINDOWS_DRIVES` moves the drives' root.
- `/my-usage` and the new personal key dialog on the Tenants page show two
  lines: one for macOS, Linux and WSL, one for PowerShell on Windows. The
  dialog has a second copy button.
- The Oh My Pi extension runs `powershell.exe -File` for the PowerShell
  `aigw-token` on Windows.
- The installers swap the plugin's marketplace folder in two renames.
  Claude Code loads a plugin from a directory marketplace in place at each
  session's start, so the new files apply from the next session.

## Added

- **Windows.** `GET /clients/install.ps1` and `GET /clients/aigw-token.ps1`,
  for Windows PowerShell 5.1 or PowerShell 7.
  - `install.ps1` does what `install.sh` does. It puts `aigw-token.ps1` in
    `%USERPROFILE%\.local\share\aigw`, off the `PATH`: there PowerShell
    would pick it before `aigw-token.cmd` and refuse it under the default
    execution policy.
  - `aigw-token.cmd` goes in `%USERPROFILE%\.local\bin`, for people.
  - Claude Code and omp get `powershell.exe -NoLogo -NoProfile
    -ExecutionPolicy Bypass -File "<the .ps1>"`.
  - The installer writes Claude Code's settings with PowerShell's JSON, with
    no `node`. Without `node` it leaves out the plugin and the status line,
    which need it.
  - `aigw-token.ps1` keeps the same files as the `sh` one in
    `%USERPROFILE%\.config\aigw`, so the plugin and the extension find the
    key, and each helper takes the other's sign-in.
  - Both files are ASCII, which `TestPowerShellFilesAreASCII` checks:
    Windows PowerShell 5.1 reads a file without a byte order mark in the
    system's code page.
- **Machines follow the hub.**
  - **The version.** `clients_version`, in the answers of `POST
    /api/v1/token` and `GET /api/v1/my/models`, is the first 12 hex digits
    of a SHA-256 over the client files and the plugin's archive. The
    installers keep the version they installed in `~/.config/aigw/clients`.
  - **When.** When a token's answer names another version, or a week after
    the last setup (`AIGW_UPDATE_DAYS`), `aigw-token` runs the installer
    again from the hub, in the background, with nothing shown and its
    output in `~/.config/aigw/update.log`.
    - Every descriptor is sent there, as Claude Code waits for an
      `apiKeyHelper`'s output to end. On Windows it starts with
      `Start-Process -WindowStyle Hidden`.
    - In this update mode the installer asks for nothing and stops if
      signed out. It keeps the gateway address given by hand at the last
      run (`~/.config/aigw/gateway`) and skips the gateway's check.
  - **Limits.**
    - A try that has not finished a setup is not made again for a day.
      After a setup, the next version is taken at once.
    - It never runs on a machine set up by hand.
    - `AIGW_AUTO_UPDATE=0` turns it off.
    - A hub upgrade that changes no client file moves nobody.
  - **Trust.** The hub's `/clients/` files become code that runs on every
    set-up machine within minutes of a change. See
    [security](../security.md).
- CI fails when `pwsh` is missing, so the PowerShell tests cannot skip
  there.

## Fixed

- On Windows the setup did not work: neither Claude Code nor Oh My Pi
  could run the `sh` `aigw-token`, and the installer could mix Windows' and
  WSL's programs. The reported "ELF" message itself was not reproduced. A
  Linux program (ELF) run on Windows' side, or a Windows one from WSL, fails
  in that way.

## Tested

On 2026-10-25, on macOS with Node 26:

- `node --test clients/claude-code/scripts/ clients/aigw-token/
  clients/install/ clients/omp/`. On macOS the PowerShell tests skip,
  because there is no `pwsh`. In a container (Node 26.12.1, PowerShell
  7.6.9 on Linux arm64) every test ran and passed, including:
  - `install.ps1` against the stand-in hub, run as a file and through the
    exact `iex` line `/my-usage` shows, fetched from the hub. This covers
    settings with a date-like string and a one-item list kept as they were,
    settings that are not JSON left alone, no `node`, an old hub, and a
    wrong key.
  - The PowerShell `aigw-token`: the same cases as the `sh` one, each taking
    the other's sign-in.
  - Updates:
    - another version, then a week-old setup;
    - no second try while one has not finished;
    - nothing for a machine set up by hand, or with `AIGW_AUTO_UPDATE=0`;
    - the installers in update mode;
    - no update started by an installer's own `aigw-token`.
  - The whole round with the real files: a hub upgraded to other files and
    then a fix the same day, each taken by the next token. The `sh`
    `aigw-token` printed its token in under 1.5 s while the installer was
    still running.
  - `install.sh` in Git Bash (a stand-in `uname`) and in WSL (stand-in
    Windows programs under a stand-in `/mnt/c`).
- `go test -race ./...` with Postgres 17 and Redis 7, `go vet`, gofmt,
  `hack/check-duplication.sh`, `hack/check-chart.sh`,
  `hack/check-release-note.sh`. The web tests, `tsc` and the build.
- How Claude Code 2.1.308 runs things, read from its bundled code:
  `apiKeyHelper` with `shell: true` (`cmd.exe` on Windows), a hook with
  `args` spawned with no shell, the status line through Git Bash. In a
  throwaway config folder, a plugin from a directory marketplace loads in
  place, so a new folder applies at the next session. How omp runs a
  `!command` on Windows, from its source: its own shell, brush.

Not run:

- Anything on Windows: neither Windows PowerShell 5.1, Claude Code on
  Windows nor omp on Windows. The hidden `Start-Process` that keeps the
  update off Claude Code's handles was not run either.
- WSL itself.
- The reported ELF message.
- The sandbox hub and the lab: no live run.
