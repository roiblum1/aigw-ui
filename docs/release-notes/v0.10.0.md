# 0.10.0 (not released yet)

A model can be given prices. Its quotas and usage are then counted in
dollars, and a prompt answered from the prefix cache costs less.

Nothing changes for a model without prices.

## Prices

- **Three prices per model**, each for a million tokens: input, cached
  input and output. **Prices** in a model's row on the Models page.
- **The gateway computes the cost.** The server writes a cost expression
  from the prices into the model's `QuotaPolicy`. No request passes through
  the hub.
- **Dollars in the interface.** Limits are entered and shown in dollars for
  a priced model, and the Usage page and the Overview show money. The
  Overview shows dollars or tokens, one at a time.
- **Prices start at 00:00 UTC**, when every quota window starts anew. The
  server makes the change by itself.
- **A model's first prices convert its limits** from tokens, at the input
  price, and put it in **dry-run**: every tenant is counted and nobody is
  refused, until you switch dry-run off in the Prices dialog.

[Charging by cost](../pricing.md) explains the arithmetic, how to set a
price that only recovers cost, and what is not charged.

## Before you price a model

1. Upgrade to 0.9.2 first and run the self-test: its new steps show whether
   the model reports cached tokens and whether a request is charged to the
   tenant of its key.
2. Pick a model with one site. On an entry route with two or more sites the
   gateway counts nothing yet.
3. Expect a time without enforcement. In dry-run the model's token quotas
   are not enforced either.

## API

- New: `GET` and `PUT /models/{id}/prices`, `DELETE
  /models/{id}/prices/pending`, `PUT /models/{id}/prices/dry-run`.
- Models, quotas and the usage report carry `unit`: `tokens` or `credits`.
  A credit is $0.00001. `token_limit` and `default_limit` keep their names
  and hold credits for a priced model.
- **Changed:** `token_limit` and `default_limit` above 4294967295 are now
  refused. The gateway cannot count further, and a larger limit wrapped
  around there.

## Tests and delivery

- CI now also applies a priced model to a real Kubernetes API server with
  the gateways' definitions, and runs a first test of the UI's code: how
  dollars are shown and stored.
- **New: CI can upgrade a hub.** After the image of a commit on `main` is
  pushed, the job `deploy` runs `helm upgrade` on one hub and rolls back if
  the new pod does not become ready. It is off until the repository
  variable `HUB_DEPLOY` is `true`. See
  [operations](../operations.md#upgrading-a-hub-from-ci).

## Upgrade

```sh
helm upgrade aigw-ui deploy/chart/aigw-ui -n aigw-ui
```

One database change, applied at start: the table `model_prices` and a
column on `models`. No setting changes.

## Tested

On OpenShift 4.22 with Envoy Gateway 1.9.1 and AI Gateway 1.1.0, one site,
with a stand-in for the model server:

- The gateway charged plain and streamed requests by the rendered prices,
  the cached part of a prompt at the cached price. Each counter grew by
  the cost plus 1.
- Two tenants at once were counted apart.
- In dry-run a tenant past its limit was answered. With dry-run off it got
  429.
- The self-test passes on a priced model.

The figures are in [charging by cost](../pricing.md#tested).

Not tested: a real vLLM, the change at 00:00 UTC happening by itself, and
the conversion of limits on a gateway.
