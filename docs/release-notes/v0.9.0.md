# 0.9.0 (not released yet)

## Best-effort when a budget is spent

A model with an entry route can be set to keep answering a tenant whose
budget is spent, in place of refusing it with 429. The tenant's requests are
sent to the serving sites as the class `best-effort`: served when a site has
room, queued behind all other requests when it has not, dropped first, and
tried at the next site when one site answers 429. The tenant is back to
normal when its quota's window ends.

- **Models page:** a selector per model: refuse (the default), best-effort,
  or best-effort also for tenants without a quota on the model.
- **Usage and Tenants pages:** a "best-effort until" badge, the tokens used
  as best-effort, and a list of earlier periods.
- **API:** `PUT /models/{id}/spent`, `GET /overage`, and `overage_used` and
  `best_effort_until` in `GET /usage`.
- **Self-test:** a new step proves that a tenant past its budget is counted
  on the best-effort route.
- **Settings:** `config.overageInterval` (15s) and `config.overageThreshold`
  (0.9).

How it works and why is in
[what each action does](../how-it-works.md#best-effort-when-a-budget-is-spent).

### Before you turn it on

- **It works for a model with one site only.** With more than one site the
  quota problem of 0.8.0 is still there: the gateway counts and enforces no
  quota on the entry route, so no budget is ever seen as spent and nobody is
  moved. See "Quotas on an entry route with one site" below.
- Every serving cluster needs an `InferenceObjective` named `best-effort`
  for the model, defined by the model's release. The hub only sends the
  name.
- A tenant that uses the last 10% of its budget within about 15 seconds
  still gets 429 until the move has reached the gateways.
- Quotas per second or per minute and dry-run quotas are not moved.
- One model lists at most 200 tenants. More than that shows a warning and
  the rest are refused.
- An overage cap, a limit on what tenants may use as best-effort, is not in
  this version.

## Quotas on an entry route with one site

A model with a single site no longer gets zone weights in its traffic
policy. There is nothing to weigh with one site, and the weights were what
made the gateway skip the route's quota. So on a fleet of one cluster, the
entry route enforces quotas, and best-effort mode works.

With a second site the weights come back and with them the problem: every
tenant is answered without a limit. The model's row on the Models page then
shows a warning. Envoy AI Gateway 1.2.0 does not fix this. A fix is
prepared for the upstream project.

## A new quota now reaches the proxy without another change

In Envoy AI Gateway 1.1.0 a quota added to a tenant whose key already
existed was neither counted nor enforced until something else changed on
the gateway. Routes the hub renders now carry an annotation that changes
with the quota rules, which makes the gateway rebuild the route. This does
not cover a route that a cluster's own chart renders: there a new quota
takes effect with the next key change.

## Upgrading

The database gets two new columns on `models` and the table `overage`. No
setting has to change: every model stays on "refuse".

## Tested

Envoy Gateway 1.9.1 and Envoy AI Gateway 1.1.0 on OpenShift 4.22, one fleet
cluster, a stand-in model.

| Check | Result |
|---|---|
| Entry route with zone weights, tenant limited to 30 tokens | 10 of 10 answered, nothing counted (the 0.8.0 problem) |
| Same without zone weights, which is what a one-site model now gets | 5 answered, then 429 |
| Best-effort on, tenant at 38 of 30 tokens | Moved after 4 s, answered from 18 s on. One request got 500 while the route was being added |
| Class seen by the serving site | `best-effort` for the moved tenant, `standard` for another; a class sent by the client is replaced |
| Counters | 99 tokens on the best-effort route, the model's own counter unchanged |
| Usage reset | Tenant back on the model's route as `standard` |
| Quota added to a tenant with an existing key | Before: never enforced. Now: 429 at the limit 12 s later |
| Self-test with the new step | Passed |

Not tested: a second site taking a request after a 429, a real model
dropping best-effort requests under load, and a window ending by itself.
