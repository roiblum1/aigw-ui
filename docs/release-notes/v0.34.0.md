# 0.34.0 (2026-10-21)

A personal key works while the gateways still take API keys. One line from
the hub sets up Claude Code with the person's models and Oh My Pi, whose
extension adds those models to omp. The gateway's address is its root, and
an address that ends with `/anthropic` or `/v1` is taken as well.

## In short

**What was wrong.** Three things kept 0.33.0's one-line setup from working
on a real fleet:

1. A fleet that still has API keys (`sk-…`) checks every request against
   the list of API keys first, before it looks at a token's signature.
   The tokens `aigw-token` gets for a personal key were not on that list,
   so the gateway refused them with 401, though the hub had signed them.
2. Claude Code was not told which models to ask for. It asked the gateway
   for Claude's own models, which the gateway does not serve.
3. The gateway's address had to be set with `/anthropic` at its end, the
   path of the gateway's Anthropic API, although the docs said the bare
   address.

**What 0.34.0 does.**

1. While a fleet has API keys left, the hub puts each personal key's token
   on that list. It gives a person's helper the same token on every
   renewal and changes it only every few days, so a renewal every 10
   minutes does not mean a change to every gateway every 10 minutes.
2. The hub tells each person's tools which models they may call, with
   their lengths and prices. It asks each model server for its real length
   itself, since vLLM often picks it, so nobody has to declare it. Claude Code gets one model to work with and a
   small one for background tasks. You choose them, or the hub takes the
   tenant's priciest and cheapest.
3. The same line now sets up Oh My Pi too. Its extension adds the person's
   models to omp each time it starts, with their prices, so omp counts the
   cost; the installer makes the same two models omp's default and quick
   model. Nobody edits `models.yml`.
4. The gateway's address is its root. The hub adds `/anthropic` for
   Claude Code and `/v1` for Oh My Pi, and an address already ending with
   either is taken as well.

**What to do.**

- **Admin:**
  - Set `config.gatewayURL`.
  - Choose Claude Code's models with `config.claudeCode`, or leave them to
    prices.
  - Give each person a personal key. The Tenants page shows the line to
    send them with it.
- **Each person** runs the line once. It asks for the key, sets up what is
  installed (Claude Code, Oh My Pi, or both), and checks that the gateway
  takes the token:

  ```sh
  curl -fsSL https://<the hub>/clients/install.sh | sh -s -- https://<the hub>
  ```

  People who ran the 0.33.0 line run it again.
- **Moving to tokens only.** A fleet in the middle of the switch from API
  keys works now, but it is best finished: give the tenants that still
  have API keys a token each, then revoke their keys. Budgets across
  models, model lists and quotas by amount are enforced only once no API
  key is left.

Database: migration 036 adds the table `personal_tokens`.

## Upgrading

- Set `config.gatewayURL` to the gateway's address without an API's path,
  such as `https://llm.example.com`. One set for 0.33.0 with `/anthropic`
  at its end, as Claude Code needed then, is taken without it.
- Optionally set `config.claudeCode.model` and `config.claudeCode.smallModel`
  to the models Claude Code should work with and use for its background
  tasks. Without them each tenant gets its priciest and its cheapest model.
- People who ran the 0.33.0 installer run it again: it adds the models
  Claude Code asks for, which 0.33.0 did not set, and sets up Oh My Pi.
  The line no longer needs the gateway's address.
- `helm upgrade --reuse-values` from 0.33.0 works: the chart reads
  `config.claudeCode` only when it is there.
- While the gateways take API keys too, each personal key's first renewal
  after the upgrade stores a token and queues a sync, and that token is
  refused for the seconds the sync takes. With tokens only, nothing
  changes.

## Added

- **The hub reads each model's real length.** Discovery asks one ready pod
  of each deployment that declares no `aigw-ui.io/max-model-len` for its
  `/v1/models`, where vLLM reports the `max_model_len` it chose. The request
  goes through the Kubernetes API's pod proxy, at the scheme and port of
  the pod's readiness check, once per pod; a pod that does not answer is
  asked again after 10 minutes. The annotation, where set, still wins.
  - The length shows on the Models and Capacity pages, feeds the warning
    when sites take different lengths, and goes to the clients.
  - It needs `get` on `pods/proxy` for the workload pods; without it the
    length is the declared one, or the market's, and the cluster's
    discovery message says `not allowed to get pods/proxy`.
- **`GET /api/v1/my/models`**, with a tenant's key: the gateway's root and
  its two APIs (`/anthropic`, `/v1`), the models the tenant may call that
  have an endpoint, and Claude Code's two models.
  - For each model it gives the length: the least of its deployments,
    declared or read from its servers, or else the market's figure. It gives prices in
    dollars per million tokens.
  - Claude Code's models are `config.claudeCode` where the tenant may call
    them. Otherwise they are its priciest and its cheapest model, by output
    price, then input price.
- **The installer sets up Claude Code with models.** Run as
  `curl -fsSL <hub>/clients/install.sh | sh -s -- <hub>`, it now:
  - gets the gateway and the models from the hub;
  - for Claude Code, writes `ANTHROPIC_BASE_URL` as the gateway with
    `/anthropic`, and `ANTHROPIC_MODEL` with the alias models (Opus,
    Sonnet, Fable, Haiku, small-fast). A model the person set that they
    may call is kept;
  - when the hub knows the model's length, writes
    `CLAUDE_CODE_MAX_CONTEXT_TOKENS` and `CLAUDE_CODE_MAX_OUTPUT_TOKENS`
    (a quarter of it, at most 32,000). Claude Code otherwise takes an
    unknown model for 200,000 tokens long and asks for answers of 32,000,
    which a shorter model refuses;
  - sets up each tool only when it is installed;
  - checks at the end that the gateway takes the token, waiting up to 60 s
    while the gateways list it.
- **Oh My Pi.**
  - The installer puts the extension in `~/.omp/agent/extensions`, and
    sets omp's model roles: `default` to the same model as Claude Code's,
    `smol` (omp's quick tasks) to the small one, so plain `omp` uses the
    gateway. A role set to another provider is kept; one on a gateway
    model the person may no longer call is replaced.
  - The extension now registers the tenant's models as the provider `aigw`
    when omp starts: on the gateway's `/v1`, with lengths, prices and
    `!aigw-token` for tokens. Nothing is written to `models.yml`.
  - It keeps the last list for when the hub cannot be reached.
  - A provider `aigw` of the person's own in `models.yml` is left alone,
    and omp says so.
- **The Tenants page** shows the installer line when a personal key is
  made, in place of the hand-written settings, with **Copy key** and **Copy
  line**. The line wraps here and on `/my-usage`, so it is read whole.
- **`/my-usage`**: the panel is **Set up Claude Code and Oh My Pi**. It
  names the models each tool gets, says when the hub has no gateway address,
  and its step-by-step settings carry the models.
- Chart values `config.claudeCode.model` and `.smallModel`
  (`CLAUDE_CODE_MODEL`, `CLAUDE_CODE_SMALL_MODEL`).

## Fixed

- **A personal key's tokens were refused while the gateways took API keys
  too** (401 `Client authentication failed`, seen on a fleet with 9 API keys
  left). Envoy runs the API key check before the JWT check, and it lets
  through only what the Secret `aigw-ui-api-keys` lists. The tokens a
  personal key got were never stored, so never listed. The installer and
  `aigw-token` of 0.33.0 did not work on such a fleet.
  - Such a token is now stored, encrypted, and listed under the tenant's
    slug and its `jti`.
  - So that a renewal every 10 minutes does not mean a sync every 10
    minutes, the helper gets the same token on every renewal. A new one is
    signed at half its life (3.5 days by default) and given out two minutes
    later, once the sync has taken it to the gateways. A key has at most
    two listed at a time.
  - A key made while API keys are taken gets its first token when it is
    made, so the gateways have it before its owner signs in.
  - A revoked key's tokens leave the list, and stay refused by their `cid`.
    With tokens only, nothing is stored, as before.
  - The self-test syncs before it sends the personal key's token in that
    mode.
- **Claude Code asked for Claude models.** The 0.33.0 installer set no
  model, so Claude Code asked the gateway for `claude-…` models it does not
  route.
- **The gateway's address was taken as it was.** Claude Code adds
  `/v1/messages` to `ANTHROPIC_BASE_URL`, and the gateway's Anthropic API is
  at `/anthropic/v1/messages`. So `config.gatewayURL` had to end with
  `/anthropic`, against what the docs said.

## Tested

- `go test -race ./...` with Postgres 17 and Redis 7 (328 tests), with:
  - the personal-key tokens in both mode, with a moved clock: listed before
    any renewal, the same token on renewals, a new one at half its life
    given out two minutes later, two at most, gone from the list when
    revoked, none stored with tokens only;
  - one sync queued for a key that had no token;
  - `GET /my/models` with prices, an unserved model, a tenant held to
    models, the operator's Claude Code models and the fallback by price;
  - `GATEWAY_URL` with `/anthropic`, `/v1` and a prefix.
  - a model server's own length, through a stand-in for the API server's
    pod proxy: over HTTP and HTTPS, prefill and unready pods not asked,
    one question per pod, a refusal asked again after 10 minutes and
    reported, a pod that is gone forgotten, the annotation winning.

- A local hub on a fresh database, with `GATEWAY_URL` ending in

  - It signed in, wrote Claude Code's settings with the gateway plus

    `omp -p --model aigw/big` streamed `/v1/chat/completions` with the token.
- Both mode on that hub:
  - A key made after an API key got the same token on three renewals.
  - A key from before got one stored token and one `key.renew` sync.
