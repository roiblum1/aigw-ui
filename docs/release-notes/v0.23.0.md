# 0.23.0 (not released yet)

A tenant's budget across models and its list of models travel in its
tokens, and one gateway rule holds every tenant to its own: the gateway
configuration is the same size for a thousand tenants as for one.

Database: migration 028 drops `tenants.budget_slot` (a budget no longer has
a position) and adds `tenants.limits_changed_at`; migration 029 adds
personal keys (`api_keys.kind` `personal`, `key_hash`, `renewed_at`),
`signing_keys.renewed_until` and `client_denials`.

## Upgrading

- **Every tenant with a budget across models or a list of models needs new
  tokens.** A token carries the budget and the models its tenant had when it
  was created; tokens created before this version carry neither, and until
  they are replaced the gateway holds their tenant to neither. The tenant's
  page marks the tokens that carry older ones. For people in Claude Code,
  give personal keys instead: they renew by themselves.
- Envoy Gateway 1.9.0 or later on every cluster with budgets: the rule
  reads the amount with `limit.fromMetadata`. With an older one the budget
  does not hold, and the self-test's budget step says so.
- The counters of budgets across models get new names (the rule is now
  always the first), so what tenants used of them in the running period is
  counted from 0 once.

## Changed

- **The amount is in the token.** When the hub signs a token it writes the
  tenant's budget as `requests_per_unit` (credits) and `unit` (`MINUTE`,
  `HOUR`, `DAY`), and its models, when it has a list, as `models`. The
  budget policy has one rule for every tenant: it matches a token with a
  budget, counts per tenant, and takes the limit from the token
  (`limit.fromMetadata`). The upstream way to give each tenant its own
  number without a policy per tenant (Agent Router, formerly Envoy AI
  Gateway, "Per-Tenant Limits Without Per-Tenant Policies").
- **One rule holds every tenant to its models**: it refuses a request whose
  model is not in the token's list (403). A token without the list may call
  every model; an empty list refuses every model.
- **No limit on the number of budgets.** The 256 that Envoy Gateway takes in
  one rate limit, and the 409 past it, are gone, and so are the positions and
  the placeholder rules.
- A change of budget or models reaches the gateway with the tenant's next
  token. `GET /tenants` has `limits_changed_at`; the Keys card marks tokens
  created before it.
- The self-test gives its temporary tenant a new token after giving it a
  budget or a list of models.
- **Faster with many tenants.** With 1,000 tenants the tenants list, the
  models and a tenant's usage each took 0.1 s on the hub, because every key
  count read the whole table of keys; migration 030 indexes the keys and
  best-effort periods by tenant (6, 7 and 13 ms). The hub gzips its answers
  (not those with a secret in them), the browser keeps the UI's built files
  for good, a tenant's page loads its parts at once, and a page shown before
  shows at once while it loads anew. The Tenants list has a search box. Over
  a slow link the list opens in 0.4 s instead of 1.2 s and a tenant in 0.2 s
  instead of 0.55 s (see performance.md).

## Added

- **Personal keys.** **Create** on the Keys card makes a personal key
  (`aigw-pk-...`) or a token. The new helper `clients/aigw-token`, Claude
  Code's `apiKeyHelper`, trades the key at the hub (`POST /api/v1/token`)
  for a token that lives `tokens.renewedLifetimeHours` (168) and carries the
  tenant's budget and models as they are then, and gets a new one every 10
  minutes. A change reaches the person with nothing to do. The hub keeps
  only the key's hash, and the gateways never see it; the tokens are not
  stored. Revoking the key refuses its tokens by their client ID until the
  last one expires. The tenant's page takes a personal key to sign in, and
  the status-line plugin finds the one `aigw-token` signed in with.
- A self-test step: a personal key gets a token the gateway takes, which is
  refused once the key is revoked.

## Fixed

- **Manage** on the Tenants page showed an empty page for every tenant: the
  page called one React hook only once the tenant had loaded (React error
  #310). It came with the choice between a personal key and a token.

## Why

With a rule per tenant the gateway took at most 256 budgets, and every rule
cost about 1.2 KB on every route of the client listener. At 256 tenants on a
listener of 10 routes that was 3.2 MB of routes, and a change took 11 to 19
seconds to reach the proxy, against 3 seconds with 4 tenants (lab,
2026-10-16). The time a request took did not change. A thousand tenants
were out of reach.

## Tested

On the sandbox hub running this version and the lab gateway (Envoy Gateway
1.9.2, AI Gateway 1.2.0 patched), 2026-10-16, with the stand-in models
priced at $15/$1.50/$75 (opus), $3/$0.30/$15 (sonnet), $1/$0.10/$5 (haiku)
per million tokens and new tokens for the test tenants:

- The hub renders one budget rule and one models rule; the lab's Envoy
  Gateway accepts them, keeps `fromMetadata`, and merges the budget policy
  with the entry route's.
- A tenant held to opus: opus 200, every other model 403, on the Anthropic
  path too; `GET /v1/models` answered. Held to opus and sonnet: both 200.
- A $1 budget read from the token: opus and sonnet charged together, then
  429 on every model, a model without prices and the Anthropic path
  included; the control tenant served. A $0.20 quota on opus refused opus
  while the $0.50 budget had room, and sonnet spent the rest. The same
  results, to the credit, as with a rule per tenant.
- Cached input: 10,000 tokens of which 8,000 cached cost $0.042 against
  $0.15 uncached, on chat, streaming chat, Anthropic and streaming
  Anthropic.
- A personal key with `aigw-token` against the hub: signed in, its files
  readable by the user only, a token of 168 hours with the budget. The
  budget spent, the next request refused; the budget raised on the hub, the
  next token carried the new amount and the same user was answered, with
  nothing to do. The key revoked: its token refused with 403 five seconds
  after the sync, and the hub answered 401 to it.
- The self-test on qwen-tiny passed every step it runs there, the new
  personal-key step and the budget and models steps included. In
  best-effort mode its best-effort step passed: the tenant was answered
  past its budget and counted on the best-effort route.
- The shared pool: a tenant past its own quota was served from the model's
  pool until the pool was used up, then refused; a tenant with quota left
  was served after.
- What a budget adds: one round trip to the shared Redis, 38 ms against 69
  ms at p50 with Redis 33 ms away, as with a rule per tenant.
- The hub with 1,000 tenants with budgets, 500 held to a model and a token
  each (locally): a budget policy of 771 bytes and a SecurityPolicy of
  1.4 KB, the same as for two; rendering in 13 ms, the usage report of every
  budget in 590 ms, a token renewal in 1.6 ms.
- 1,000 tenants on the sandbox hub, each with a personal key and a budget,
  100 with an own Opus quota: no change in what a request costs (38 and 69
  ms), the budget and token policies the same size, only the Opus and
  Sonnet `QuotaPolicy` grown by one rule per own quota; tenants held to
  their budget, list and quotas as with 25. All 1,000 deleted again.
- `npm run build` runs `oxlint`'s `rules-of-hooks` first, which finds the
  hook that left the tenant's page empty.

Found and fixed on the way: `aigw-token login` stopped without a word on a
key piped without a newline at the end, and the self-test's tenant-header
step failed on a model with a standard in best-effort mode, though the
gateway was right.
