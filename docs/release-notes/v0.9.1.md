# 0.9.1 (not released yet)

Fixes for best-effort mode from a review of 0.9.0, tidier code, and more
tests. Nothing changes for a model that refuses a spent budget, which is
every model unless you switched one.

## The hub creates the request class itself

Best-effort mode needed an `InferenceObjective` named `best-effort` on
every serving cluster, which the model's release had to bring. The hub now
creates it.

- For a model in best-effort mode, every cluster that serves it gets an
  `InferenceObjective` `best-effort` with priority -1, in the namespace of
  the model's `InferencePool`. It is removed when the model goes back to
  refusing.
- The pool is read from the status of the model's `LLMInferenceService`,
  at the poll that already reads the ready instances. KServe creates the
  pool for a service that has a scheduler.
- A site that serves the model without a pool shows as a warning on the
  model's row. A cluster without the `InferenceObjective` kind is synced
  as before, and the task says the class was left out.
- New setting `config.bestEffortPriority` (`-1`).
- If a release already defines an `InferenceObjective` called
  `best-effort` in the model's namespace, the hub takes it over: it sets
  its priority and pool and removes it when the mode is switched off.
  Remove it from the release.

Checked against the real CRD on a test API server: the object is accepted,
sits in the model's namespace, and is removed again. Not run on a serving
cluster: that the scheduler drops these requests first under load.

## Fixes in best-effort mode

- **The 200-tenant limit drops the right tenants.** A model's best-effort
  route lists at most 200 tenants. Tenants whose budget is spent are now
  listed first and tenants without a quota after them. Before, the list was
  cut by name, so a tenant the server had moved could be left out: the Usage
  page said "best-effort" and the gateway answered 429.
- **New object names.** The best-effort objects of a model are now called
  `fleetbe-<model>` (were `fleet-<model>-be`). A model `x` in best-effort
  mode and a model `x-be` with an entry route used to write the same
  objects and overwrite each other at every sync. See "Upgrade" below.
- **Self-test on a cluster outside the fleet.** For a best-effort model the
  self-test skipped the steps "over the limit" and "reset" on every
  cluster, and then failed. A cluster without the entry route has no
  best-effort route and does refuse, so these steps run there again and the
  best-effort step is skipped.
- **After a restart.** If a tenant's best-effort period ended while the
  server was not running, the tenant stayed on the best-effort route until
  the next periodic sync. The server now has the clusters synced once after
  it starts, when any model is in best-effort mode.
- **Less in the logs.** Every tenant that moved wrote its own task and its
  own audit line. Now one look of the server writes one task for all the
  tenants that moved, and no audit line. The periods are on the Usage page.
  The audit log is for what people changed.
- **Usage reset.** A reset ends the best-effort period first and deletes
  the counters second. Before, a database error after the counters were
  deleted was reported as a failed reset although the usage was gone.
- **Usage page.** A best-effort model without any quota showed a pool of
  "0 of 4,294,967,295". It shows no pool now.
- **New warning.** A best-effort model shows a warning when auto sync is
  off: a tenant past its budget is then only moved when someone presses
  Sync.

Not changed: with many tenants that have long names, the list on the
best-effort route can pass the 4096 characters one header match may have,
and the cluster then refuses the route. Tenant names will come from an
external directory, and the list is to be reworked with that.

## Upgrade

Only for a model that is in best-effort mode: the first sync after the
upgrade creates the `fleetbe-<model>` objects and removes the
`fleet-<model>-be` ones. Tokens used as best-effort are counted under the
new name, so that number on the Usage page starts at 0. Budgets and their
counters are not touched.

## Code and tests

No change in behaviour.

- Large files are split by what they do: quota, key and route rendering,
  the entry route's policies, the model warnings, the cluster form, the
  self-test's quota steps, discovery.
- Repeated code is gone: one helper reads a list from the database, one
  reads `?limit=`.
- New tests: the database layer against a real PostgreSQL (migrations,
  tenants, keys, quotas, best-effort periods), the settings, and the
  encryption of stored secrets.
- The workflow now also runs the tests with the race detector, fails on
  repeated code, and renders the chart with the settings it is installed
  with.
