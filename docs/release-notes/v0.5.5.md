# 0.5.5 (2026-10-08)

The version jumps from 0.4.0 to 0.5.5. There is no 0.5.0 to 0.5.4.

## New

- **Overview charts.** With usage monitoring on, the Overview has a "Token
  usage right now" card that refreshes every 5 seconds:
  - allocated against used, as a donut;
  - share of the tokens used, by tenant and by model;
  - the five quotas closest to their limit;
  - how full each model's shared pool is;
  - tokens per minute, measured while the page is open. Nothing is stored;
  - how many quotas are at the limit, above 80%, unused, or on dry run.

  Quotas with different windows are never added together. Buttons pick the
  window. The charts are plain SVG, so there is no new dependency.
- **Shared pool usage.** `GET /api/v1/usage` now returns `pools`: the usage
  of each model's default bucket, which every request to the model is
  charged to.
- **Borrowing unused tokens.** The model setting "Pool for tenants without a
  quota" is renamed **Shared pool**, and the user guide explains how to use
  it to let tenants use what others leave unused: set it to what the model
  can serve in the window. Each tenant quota is then a guaranteed share.

## Changed inside, same behaviour

The code was reorganised so that each file has one job. Nothing in the API,
the UI or the objects applied to the clusters changed.

- `internal/api` and `internal/store`: one file per resource (clusters,
  models, tenants, tasks, usage) instead of one large file each.
- `internal/usage`: building the usage report and resetting a counter moved
  here from the HTTP layer. The handlers now only translate HTTP.
- `internal/kube`: `Sync` is split into an apply step, a prune step and a
  status step, in their own files.
- UI: pages moved to `web/src/pages`, the charts to `charts.tsx`, the
  repeated refresh timer into one `usePolling` hook, and the styles of each
  feature into `web/src/styles`.

## Upgrade

No migration and no setting to change.

```sh
helm upgrade aigw-ui deploy/chart/aigw-ui -n aigw-ui --reuse-values
```

## Not verified: check these before relying on this release

Everything in the [0.4.0 list](v0.4.0.md#not-verified-check-these-before-relying-on-this-release)
still applies, except item 2: reading Redis through an OpenShift Route was
verified on OpenShift 4.20. New in this release:

| # | What is assumed | How to check | If it is wrong |
|---|---|---|---|
| 15 | The shared pool's counter is named `rule-<number of tenant rules>-match--1`, as in the gateway's source | Send requests to a model that has a tenant quota. The model's bar under "Shared pool per model" must move | The pool bars stay at 0 while the tenant bars move. Nothing else is affected |
| 16 | A request is let through while either the tenant's quota or the shared pool has tokens left, as the gateway documents for `Shared` mode | Set a pool larger than a tenant's quota, go past the quota, and check that requests are still answered until the pool is used up | Borrowing does not work, and tenants stop at their own quota whatever the pool is |
