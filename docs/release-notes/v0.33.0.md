# 0.33.0 (2026-10-19)

A person sets up Claude Code from the tenants' page, with everything coming
from the hub, so it works in a network with no internet. An admin can show
a token in full again. A capacity measurement of a model that does not
declare its length is scaled to the model instead of refused. The market
search finds "Qwen 3.8".

Database: no migration.

## Upgrading

- Set `config.gatewayURL` to the address clients send their requests to,
  so that the setup on `/my-usage` names it. Without it the line leaves
  the address out and the page says to set it.
- Nothing changes on the clusters.
- A capacity run that is going on at the upgrade finishes with the settings
  it started with.

## Added

- **Set up Claude Code on `/my-usage`.** After a sign-in with a personal
  key, the page shows one line to run in a terminal:
  `curl -fsSL <hub>/clients/install.sh | sh -s -- <hub> <gateway>`. It
  installs `aigw-token` in `~/.local/bin` and signs it in (it asks for the
  key on the terminal), sets `apiKeyHelper`, `ANTHROPIC_BASE_URL` and the
  status line in `~/.claude/settings.json` (every other setting is kept,
  the old file is kept as `settings.json.aigw-backup`), and installs the
  `aigw-usage` plugin with `claude plugin`. Below it, the same step by step,
  and the Oh My Pi extension. Signed in with a token or an API key, the page
  says a personal key is needed. The sign-in form now asks for a personal
  key, and still takes any key or token of the tenant.
- **The hub serves the client files** at `/clients/` with no sign-in, from
  its binary (`clients/embed.go`): `install.sh`, `aigw-token`,
  `aigw-usage.ts`, and the Claude Code plugin as the marketplace `aigw` in
  `claude-code.tar.gz`. Until now they came from GitHub
  (`raw.githubusercontent.com`, `/plugin marketplace add roiblum1/aigw-ui`),
  which a disconnected network does not reach.
- **Show a token again.** Each token and API key on a tenant's page has
  **Show**, which shows it in full (`POST /api/v1/keys/{id}/reveal`), in the
  audit log as `key.reveal`. A personal key cannot be shown, as the hub
  keeps only its hash; a revoked key is not shown either (409).
- `config.gatewayURL` (`GATEWAY_URL`): the gateway's address for that
  setup; `GET /api/v1/my/usage` returns it as `gateway_url`.

## Changed

- **A capacity measurement fits the model's length.** When the model does
  not declare `aigw-ui.io/max-model-len`, as when vLLM chooses its length,
  the Job scales the settings to the length the pod lists under
  `/v1/models`, by the rule the hub uses with the annotation: the longest
  prompt is the length less the longest answer, and when that leaves less
  than twice the answer, the answer is a quarter of the length. It prints
  them (`AIGW-FIT`), and the run keeps them and is judged by them. Up to
  0.32.1 the Job stopped with "the model takes at most N tokens …" (seen
  with Qwen 3.8 27B, Qwen 3.6 35B A3B and GLM 5.3). It stops only for a
  model that takes under about 1,334 tokens, where no prompt of 1,000 fits.

## Fixed

- **The market search matches each word on its own.** "Qwen 3.8" found
  nothing, as the catalog writes "qwen3.8"; it now finds the six Qwen3.8
  entries, in any order of the words, in the id, the Hugging Face id or the
  name.

## Tested

On 2026-10-18, before the merge:

- `go test -race ./...` with Postgres 17 and Redis 7 (320 tests);
  `hack/test-apiserver.sh`; `go vet`, staticcheck v0.8.2,
  `hack/check-duplication.sh`, `hack/check-chart.sh`,
  `hack/check-release-note.sh`; the web tests, `tsc` and build; `node --test`

  `clients/install/` (15), the last two also under dash (Debian, as CI's

  8,192 and 40,960 the settings and sessions it fitted equal what
  `Profile.Settings` and `Agentic` give for that length, and the run
  finished; at 1,200 it stopped before making any session. The hub stores
  the fitted settings and judges the run by them (benchmark and store
  tests).

  created, with `Cache-Control: no-store`, and 409 for a personal key; both
  are in the audit log. `GET /my/usage` returned `gateway_url`. The installer,
  piped from the hub as `/my-usage` shows it, in an empty home with Claude
  Code 2.1.292: `aigw-token` signed in and printed a token, the settings
  were written, and `aigw-usage@aigw` was installed and enabled from the
  hub's archive, with the hub address set; `claude plugin validate` passed
  on the archive's marketplace and plugin. "Qwen 3.8" in the market search
  gave the six Qwen3.8 entries.
