# 0.9.2 (not released yet)

A fix for quotas that were not enforced, and groundwork for charging by
cost: the hub now refuses a cost expression the gateway would not use, the
self-test checks two things a price depends on, and one request field is no
longer passed to the model server.

Nothing changes in how a request is charged.

## A new quota was not enforced until something else changed

A quota given to a tenant on a route the hub renders could stay without
effect: the tenant was answered and nothing was counted, until a key or
another object changed.

- **Cause.** The gateway attaches a tenant's rule when Envoy Gateway
  builds the route again. The hub marks its routes with an annotation that
  changes with the quota rules, to make that happen. Envoy Gateway 1.9.1
  only looks at annotations whose name begins with
  `gateway.envoyproxy.io/`, and the hub's began with `aigw-ui.io/`.
- **Why it went unseen.** A new tenant gets a key in the same sync. The
  changed key list made Envoy Gateway build the route, and the quota was
  usually there in time. From a hub far from the cluster it was not.
- **Fix.** The annotation is now
  `gateway.envoyproxy.io/aigw-ui-quota-revision`.
- **Not covered.** A model the cluster's own chart brings has a route the
  hub does not write. A quota added there to a tenant whose key already
  existed still waits for the next change. The fix for that is upstream,
  after AI Gateway 1.2.0.

## Cost expressions are checked by the gateway's rules

The gateway does not refuse a quota's cost expression it cannot use. It
writes a line to its log and then charges nothing for the model. Until now
the hub only looked for typing mistakes.

- The server compiles and runs an expression the way the gateway does
  before it saves it. An expression with a number without `u` next to a
  count, a result that is not a whole number, or an unknown name is refused
  with 400.
- Comparisons and `? :` are now accepted, and the limit is 1000 characters.
  An expression that charges cached prompt tokens less needs both.
- **Check your models.** An expression saved before this version is not
  checked again. Open each model that has one and save it: a refusal means
  the gateway was not charging that model.

The user guide has an expression that charges the cached part of a prompt a
tenth. `input_tokens` includes the cached part, so it has to be subtracted
first.

## Self-test

- **The counter step compares amounts.** It works out what the first
  request should cost, also for a model with a cost expression, and
  compares it with the counter. It fails when the request was counted and
  its cost was not.
- **A client cannot choose its tenant.** A request with the tenant's key and
  another client ID in `x-aigw-client-id` must be counted for the tenant of
  the key.
- **The model reports cached prompt tokens.** The answer to a repeated
  prompt must say how much came from the prefix cache.
- The test request has a prompt of about 300 tokens, where it had a few. A
  run uses a few thousand tokens of the model, not a few dozen.

## `kv_transfer_params` is removed from requests

Every `AIServiceBackend` the hub creates now removes `kv_transfer_params`
from the request body. With it a client can set the cached token count of
its own answer on vLLM 0.31, and is reported to stop the server on 0.29 and older.

- At the first sync after the upgrade, the `AIServiceBackend` objects and
  the routes of entry routes and of models added by hand change on every
  cluster.
- Backends of discovered models are not the hub's. See
  [deployment](../deployment.md#before-cached-prompts-are-charged-less).

## Upgrade

```sh
helm upgrade aigw-ui deploy/chart/aigw-ui -n aigw-ui
```

No setting changes and no database change.

## Tested

On OpenShift 4.22 with Envoy Gateway 1.9.1 and AI Gateway 1.1.0, one site,
a model added by hand, with a stand-in for the model server:

- The self-test with its new steps passes. The counter held 253 for a
  request of 252 tokens: the gateway counts 1 more than the cost.
- A request with another client ID in `x-aigw-client-id` was counted for
  the tenant of its key.
- A request with `kv_transfer_params` reached the model server without it.
- With the old annotation a tenant's quota was not counted, and with the
  new one it was.

Not tested: a real vLLM reporting cached tokens. The stand-in reported them
the way vLLM documents it.
