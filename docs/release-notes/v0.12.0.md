# 0.12.0 (not released yet)

For Envoy AI Gateway 1.2.0, which is also named Agent Router. It still works
with 1.1.0.

## Gateway 1.2.0

- **Current API versions.** `AIGatewayRoute` and `AIServiceBackend` are
  written as `aigateway.envoyproxy.io/v1beta1`. Both gateway versions serve
  it. `v1alpha1` of the two is deprecated since 1.1.0 and was what this tool
  wrote until now. `QuotaPolicy` stays `v1alpha1`, the only version it has.
- **Nothing to migrate.** The first sync after the upgrade applies the
  objects in the new version. They are the same objects.
- 1.2.0 does not fix quotas on a model with two or more sites. The model's
  warning stays. A gateway built with
  [agent-router#2833](https://github.com/theagentrouter/agent-router/pull/2833)
  on 1.2.0 was run: quotas, the self-test and best-effort with a limit all
  worked over two sites.

## Keys in `x-api-key`

- The gateway now reads a tenant's key from `Authorization` or from
  `x-api-key`. Anthropic's clients send `x-api-key` unless told otherwise,
  and got 401 until now.
- When a request has both, `Authorization` counts.

## Self-test

- New step **A long prompt is accepted.** It sends 64 KB for a model that
  does not exist. A gateway with Envoy Gateway's default limit of 32 KiB
  answers 413, and the step fails and says what to set. No model is asked.

## The Anthropic path

- `/anthropic/v1/messages` was run through 1.2.0, plain and streamed. It is
  counted and charged like `/v1/chat/completions`.
- **Cached prompts are charged in full there**, on a model served by vLLM
  or another OpenAI-style server: the gateway drops the cached token count
  on that path, in 1.1.0 and 1.2.0. This is the gateway's, not this
  tool's. [Charging by cost](../pricing.md#the-anthropic-path) has the
  measurement and the fix that was tried.

## Performance

New page [Performance](../performance.md): through gateway 1.2.0 a request
takes about 2 ms longer without a quota and 4 ms with one; one proxy pod
carried 9,400 small requests a second without a quota and 5,400 with one.
1.2.0 measured the same as 1.1.0.

## Upgrading

- Upgrade the hub before or after the gateways. Either order works.
- The first sync changes the `SecurityPolicy` `aigw-ui-api-key-auth` (the
  second header) on every cluster.
- If a self-test now fails at "A long prompt is accepted", the gateway had
  that limit before. Long prompts were being refused.

## Tested

On OpenShift 4.22 with Envoy Gateway 1.9.2 and AI Gateway 1.2.0, with a
stand-in for the model server:

- The objects written under 1.1.0 kept working after the gateway upgrade,
  and after the hub wrote them again as `v1beta1`.
- The self-test passed on a model counted in tokens and on a priced model.
- A key in `x-api-key` was accepted on both paths; a wrong one got 401.
- The new step passed with the limit set and failed with it removed.
- With a patched gateway: see above.

Not run: a real vLLM, a model behind an `InferencePool`, two real sites.
