# 0.24.0 (2026-10-16)

Own quotas take one gateway rule per amount instead of one per tenant, once
every tenant is on tokens: the amount travels in the tenant's tokens, as a
budget across models does, and a change to it touches no object on the
gateways. Answers to a review of the manifests the hub writes.

Database: migration 031 adds `quota_amounts`, the fixed position of each
amount's rule per model, kept by a trigger on `quotas`, and fills it from the
quotas there are.

## Upgrading

- Nothing to do while any tenant has an API key: quotas stay a rule per
  tenant.
- With tokens only, the first sync after the upgrade rewrites each model's
  `QuotaPolicy` by amount, and **a tenant's quota holds from its next token**:
  give the tenants with own quotas new tokens (a personal key's helper gets
  one within minutes by itself). Until then the tenant is held by the
  model's standard or pool. The counts of own quotas start again.

## Changed

- **One rule per amount.** With tokens only, the tenants with the same
  limit, window and dry-run setting on a model share one bucket rule. It
  matches `x-aigw-quota-<model>` exactly (`500000-1h`, `7-1m-shadow`) and
  `x-aigw-tenant` with `type: Distinct`, so each tenant still has a count of
  its own. Tokens carry the claim `quotas` (model slug → amount); the token
  provider copies each model's to its header. The JWT filter takes a
  client's own value of the header out first, so a tenant cannot pick an
  amount. On the sandbox run of 1,000 tenants, the 100 own Opus quotas of $5
  an hour were 100 rules; by amount they are one.
- A quota change marks the tenant's older tokens (**older limits** on the
  Keys card, formerly "older budget or models"), and the Quotas card says
  that the amount travels in the tokens.
- The self-test gives its tenant the quota before its token, and a new token
  when it raises the quota.
- The backends the hub renders for a model server remove `x-aigw-tenant`,
  `x-aigw-key`, `x-aigw-client-id`, `x-aigw-budget` and the
  `x-aigw-quota-<model>` headers: the model server has no use for them. An
  entry route's backend keeps them for the site it forwards to.

## Added

- The Models page marks a model with prices and no standard: its tenants
  without a quota of their own share the pool.

## Clients

- **The budget across models in the coding agents.** The Claude Code plugin
  and the Oh My Pi extension showed budgets per model only; they now show
  the budget across models as **All models**, in the status line when it is
  the one furthest gone, and warn when it is nearly spent or spent.
- The Oh My Pi extension finds the hub and the personal key `aigw-token`
  signed in with, as the Claude Code plugin does, so nothing has to be set.
- clients/README.md: Oh My Pi pointed at the gateway with `apiKey:
  "!aigw-token"`, and what happens to its thinking levels on each path.

## The review

- *A token with `requests_per_unit` and no `unit`.* The hub writes both or
  neither, and never 0 (the database and the API refuse it); a test now
  checks every token it signs. Envoy reads the token's limit only when both
  are there and valid, and otherwise uses the rule's own, the most it
  counts, so such a token would be counted and not held; the self-test's
  budget step fails then.
- *QuotaPolicies grow per tenant without a standard.* They grew with own
  quotas, standard or not: a standard covers the tenants without one. One
  rule per amount ends that growth.
- *A default bucket of 1.* On purpose: a tenant without an own quota or a
  standard is refused after its first request. With tokens only every
  request has the tenant header, so it matters only on a listener without
  the hub's policy. Documented in the user guide.
- *Both rate limit services fail open.* Kept on purpose: a prompt does not
  wait on Redis. operations.md says what to watch
  (`ratelimit.failure_mode_allowed`).
- *Identity headers reach the model server.* Removed on the hub's model
  server backends (above). On the client listener the JWT filter already
  removes a client's own `x-aigw-tenant`, `x-aigw-key`, `x-aigw-client-id`,
  `x-aigw-budget` and amount headers before it writes the token's: on the
  lab a forged `x-aigw-tenant` was still refused by its own spent budget.
  security.md lists the headers for the chart's ClientTrafficPolicy, for a
  listener without the hub's policy.
- *Monthly budgets.* Envoy takes `WEEK` and `MONTH` from a token; not
  offered, by choice: budgets stay per minute, hour or day.

## Tested

Before the merge, 2026-10-16:

- On the lab gateway (Envoy Gateway 1.9.2, Envoy 1.39.1, AI Gateway 1.2.0
  patched), on a test listener: a `QuotaPolicy` with two amount rules,
  `1000-1h` and `3000-1h`, and tokens naming them through `quotas`. Two
  tenants with `1000-1h` were each answered three times and refused (429)
  at 1,000 tokens on their own counters; the one with `3000-1h` at 3,000; a
  tenant without an amount was held to the pool. The same tenant with a
  forged `x-aigw-quota-…: 3000-1h` header was still refused, and no counter
  was made for it. The Redis keys were the ones `render.Counters` names.
- A forged `x-aigw-tenant` on the client listener did not move a tenant off
  its own spent budget.
- `go test -race ./...` with the store tests (the trigger's positions, the
  `quotas` claim, both budget claims or neither), `hack/test-apiserver.sh`
  (the CRDs keep the rule's two headers and the nested claim), `npm test`,
  `npm run build` with the lint, the chart check.

After the merge, on the sandbox hub running this version and the lab:

- The first sync rewrote the QuotaPolicies by amount: Opus from 8 rules to
  6 (one per amount its tenants have), Sonnet 4, Haiku 2, qwen-tiny its
  standard and 4; the token policy copies `quotas.<model>` for each.
- With new tokens, every tenant's own quota counted under its amount's rule,
  and the Usage page read it to the credit: two Opus requests of team-opus
  ($0.105), team-coding on Opus ($0.0525) and Sonnet ($0.0105), the CI
  pipeline's count-only Sonnet quota ($0.045, answered). A revoked token was
  refused (403). As expected, every model's pool counter started again,
  since the number of rules before it changed.
- The self-test on qwen-tiny passed, the counter step under an amount's rule
  included.
