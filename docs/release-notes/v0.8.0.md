# 0.8.0 (not released yet)

Do not deploy this version before the cutover order in the fleet contract
says so.

## New

- **The hub renders each model's entry route.** With **Entry route** switched
  on for a model (Models page, off by default), every fleet cluster gets a
  `Backend`, `AIServiceBackend`, `AIGatewayRoute` and `BackendTrafficPolicy`
  named `fleet-<model slug>`. Any site's gateway then takes a request for the
  model and sends the conversation to one of the sites that serve it:
  - a consistent hash on `x-claude-code-session-id`, weighted by the site
    weights;
  - a retry on the next site when one answers 503 or cannot be reached;
  - a health check on `/healthz/<model>` at each site, and no traffic to a
    site that fails it;
  - quotas attached to the entry backend alone. The model's quota counters
    restart once when the switch changes.
- **Fleet revision.** Each fleet cluster shows a short code for the entry
  routes last applied to it. A cluster that is behind the fleet is marked
  "outdated" on the Clusters page.
- **Peer host and port per cluster**, where the other sites reach its
  gateway. A fleet cluster needs the host.
- **Chart values `fleet.*`**: the domain or server name of the peer
  listeners, the CA ConfigMap, the client certificate Secret and the session
  header. Without `fleet.domain` or `fleet.peerSNI` no entry route can be
  switched on.
- **A cluster serves a model when it has an `LLMInferenceService` for it**,
  also when its own gateway has no route for the model any more. A poll that
  cannot read the deployments fails and changes nothing.

## Fixed

- **A zone weight is never 0.** 0.7.0 listed every fleet cluster in a model's
  zone weights, with 0 where it did not serve the model. Envoy rejects a
  locality weight below 1, and Envoy Gateway then stops publishing every
  change to that gateway, key revocations included. Now:
  - a model's zones are exactly the sites that serve it and are not drained
    out;
  - the weight is the capacity × 100, and at least 1. 8 instances are 800,
    2.6 is 260;
  - a serving site with nothing ready stays listed at 1. Its health check
    keeps traffic off it, and it ramps up from there;
  - a drain steps down one instance per poll to 1, and the site leaves the
    model's zones on the poll after that. Undrain lists it again at 1 at
    once, and it ramps up one instance per poll;
  - a model that would be left with no site keeps the sites and weights it
    has, and the Models page says so.

## Changed

- **Zone weights are worked out once for the whole fleet** on each discovery
  round and stored, so every cluster is rendered from the same list.
- **The hub no longer writes `weightedZones` into policies that charts
  own.** The label `aigw-ui.io/zone-weights` and the field manager
  `aigw-ui-weights` are gone. Remove the label, the annotation
  `aigw-ui.io/model` and the Argo CD `ignoreDifferences` entry from any chart
  that added them for 0.7.0.
- **A fleet cluster needs a client listener**, and all fleet clusters must
  use the same gateway namespace. The namespace is part of every quota
  counter's name, so a site with another one would count its tenants' tokens
  apart from the rest. Saving a cluster is refused otherwise.

## Tests

- The tests against a real API server each create their own namespace and
  delete it at the end, so they pass on a server that was used before.

## Upgrade

Two migrations, `010_fleet_zones.sql` and `011_fleet_entry.sql`, add columns.
The kubeconfig of each cluster must be able to list
`llminferenceservices.serving.kserve.io` in all namespaces where KServe is
installed; discovery fails otherwise.

## What was tested, and what was not

- Unit tests: the entry objects, that no object carries a zone weight below
  1, that zones and endpoints match, the guards on saving a cluster.
- Against a Kubernetes 1.37 API server with the **real CRDs** of Envoy
  Gateway 1.8.5 and Envoy AI Gateway 1.1.0 (`hack/test-apiserver.sh`): every
  rendered object is accepted, a second sync changes nothing, a site that
  leaves is removed from the `Backend` and the zones together, and switching
  off removes the objects.
- The whole loop on two simulated sites: switch on, drain to unlisted,
  undrain at weight 1, switch off.

**Not tested: a running Envoy Gateway, KServe or real traffic.** No gateway
has translated these objects, so the following are assumptions from the
sources:

| What is assumed | How to check |
|---|---|
| The gateway generates an `HTTPRoute` with the name of the `AIGatewayRoute`, so the policy attaches | `oc get backendtrafficpolicy fleet-<slug> -o jsonpath='{.status}'` shows it accepted |
| An older route for the same model keeps the traffic until it is removed | Before removing the old route, send a request and check which backend answered |
| The client certificate Secret is found in the gateway namespace | The `Backend` status, and a request that reaches another site |
| Envoy accepts the result: weights, health check, retry | `egctl config envoy-proxy cluster`, and the gateway log has no "skipped publishing" |
| The same session ID lands on the same site from every entry gateway | The self-test's stickiness step, once built |
