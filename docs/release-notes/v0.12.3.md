# 0.12.3 (2026-10-13)

Fixes for a fleet model whose sites serve it from a pool only, a steadier
health check on the entry route, and two client plugins that show a tenant
its budget.

No database change. The entry route's traffic policy is rendered again on
every fleet cluster at the first sync after the upgrade.

## The entry route's health check

The entry route checks each site every 5 seconds. A site's model server
closes an idle connection after 5 seconds by default, so a check could meet
a connection that was closing, fail, and take a healthy site out. With one
site, every request then got 503.

- **Interval.** The check runs every 3 seconds, so its connection is never
  idle long enough to be closed.
- **All sites failing.** The panic threshold is 1 instead of 0. When every
  site fails the check, requests are still sent to the sites, and are not
  refused at the entry route.
- **Measured on the lab**, one site, one proxy, the site's retry removed:
  with the old settings 6 of 54 checks failed; with the new ones 0 of 84.
  With the health route deleted, the site showed as failing and 5 of 5
  chat requests were answered.
- **On the model server.** Raising its keep-alive above the interval
  removes the cause on that side. For vLLM that is
  `VLLM_HTTP_TIMEOUT_KEEP_ALIVE`. The hub does not set it.

## A fleet model that its sites serve from a pool only

Once a site drops the model's own route and backend (the cutover step of a
fleet model), no cluster reports a backend for the model.

- **Quotas.** The API refused a new quota with "this model has no
  AIServiceBackend on any cluster" and the UI showed "no quota possible".
  A fleet model's quota attaches to the entry backend the hub renders, so a
  fleet model can now always carry a quota. Quotas that existed before were
  not affected.
- **Model card and self-test.** The card showed "no quota here" and the
  self-test skipped the model. An endpoint now carries `entry_backend`, the
  name of the entry backend, when the model is a fleet model and the
  cluster is in the fleet. The card shows it, and the self-test runs.
  See [api](../api.md).

## The budget-spent select on the Models page

The select that says what happens when a budget is spent was as wide as
its cell and higher than the buttons beside it. It now has their size.

## Plugins that show a tenant its budget

New under `clients/`: a Claude Code plugin and an Oh My Pi extension. Both
ask the hub's `/my/usage` with the tenant's own key, show the budget of the
model in use in the status line, and tell the user once when a budget is
nearly spent, spent, served as best-effort or refused. See
[clients/README.md](../../clients/README.md).
