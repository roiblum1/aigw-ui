# 0.12.2 (not released yet)

Documentation and two texts in the UI. Nothing in the hub's behaviour
changes.

## Best-effort under load was described wrongly

- The docs and the UI said that a site queues best-effort requests behind
  all others and drops them first. That is the scheduler's part, and it was
  never run under load.
- Run now, on OpenShift 4.22 with KServe 0.21 and its default scheduler
  settings, against vLLM 0.29 limited to two requests at a time: 30
  `standard` and 10 `best-effort` requests sent together, up to 28 waiting.
  Nothing was refused, and both classes waited in one queue.
- The docs now say what the hub does (marks the request, counts it apart
  from the budget, moves the tenant back when its window ends) and that the
  rest depends on each site's scheduler. A new section,
  [what a site does with the class](../optimization.md#what-a-site-does-with-the-class),
  has the test and the scheduler setting that should make the class count.
  That setting has not been run here.
- Changed: `optimization.md`, `how-it-works.md`, `architecture.md`,
  `user-guide.md`, `deployment.md`, `platform-architecture.md`, the README,
  the confirmation on the Models page and the tag's hint on the Usage page.

## Cache-aware routing between sites

A new section in
[how-it-works.md](../how-it-works.md#cache-aware-routing-between-sites): a
conversation stays on its site by the session header, and inside a site the
scheduler picks the replica that holds the prompt's beginning. A site is not
chosen by what it has cached. The section says what that costs, why it is
not built, and what to measure before changing it.
