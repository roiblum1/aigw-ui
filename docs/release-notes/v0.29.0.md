# 0.29.0 (2026-10-17)

Fixes from a review of the hub against Envoy Gateway 1.9.2, Envoy AI Gateway
1.2.0, KServe 0.21 and llm-d router v0.10.0, each checked against that
source before it was changed. A tenant's list of models now goes together
with its budget or quotas, and two details of the UI are fixed.

No database change.

## Upgrading

- Nothing to do. After the upgrade every model server's `AIServiceBackend`
  removes the credentials only, the entry routes retry a 500 too, and on a
  cluster whose client listener serves plain HTTP every retry patch is
  written for both names of the route configuration. None of it renames a
  counter. On a model added by hand, tenants' quotas and budgets start to be
  charged each answer's cost (see Fixed); what went uncounted before is not
  added.
- The hub now gets, where it may, the `Deployment` or `LeaderWorkerSet` of
  each LLMInferenceService and its `InferencePool`, the `Gateway` before
  each sync, and the HTTPRoutes whose own `SecurityPolicy` replaces the
  hub's. Without those rights it works as before; see
  [security](../security.md#kubeconfigs). Without get on HTTPRoutes in the
  gateway namespace, every sync warns about the gateway chart's health
  check where it is on (see Added).
- The hub's token check writes one more header, the tenant into
  `x-llm-d-inference-fairness-id`. The sites' schedulers label their
  request metrics with it, so tenants' slugs appear there (at most 1,000).

## Fixed

- **A model added by hand charged no tenant its cost** (since 0.24.0). On
  the lab a tenant's quota counted 1 for an answer that cost 72 credits, and
  a budget across models counted nothing for 32 answers that cost 2,328 and
  refused none; the model's pool counted every cost. Envoy Gateway charges
  an answer's cost with a second rule that reads the request's headers again
  when the answer ends (`ApplyOnStreamDone`), and the model server's
  `AIServiceBackend` had removed `x-aigw-tenant`, `x-aigw-key`,
  `x-aigw-client-id` and `x-aigw-budget` from those same headers by then.
  The backends the hub renders now remove the credentials only. Models from
  discovery and entry routes were not affected: their backends kept the
  headers.
- **The eleventh model with quotas by amount failed every sync.** A model
  server's `AIServiceBackend` removed six headers plus one
  `x-aigw-quota-<model>` per model with quotas by amount, and AI gateway
  1.2.0 takes 16 at most: from the eleventh such model on, every model
  server's backend was refused and the whole sync with it. The amounts are
  no longer removed there, and with the item above neither are the other
  four: the list is the two credentials, whatever the number of models.
- **The retry patches would match nothing on Envoy Gateway 1.10.** Under
  its xDS names of version 2, on by default from 1.10, the client
  listener's route configuration is called `http-<port>`. The patches named
  it only `<namespace>/<gateway>/<listener>`, so on such a gateway every
  forwarded request would have lost its Host and got a 404. The hub reads
  the listener's port before each sync and writes the patches for both
  names; the policy's annotation `aigw-ui.io/route-configurations` lists
  them, and the sync takes Envoy Gateway's "not found" for the name it does
  not use as in effect.
- **A capacity measurement could not reach a data-parallel pod.** It went
  to the port of the readiness probe, which on glm53 is a supervisor that
  answers health checks only (8208). It now goes to the ports of the
  model's `InferencePool` (`targetPorts`, 8000 to 8007 there), and the
  counters of all ranks are added up. AIPerf gives each session one rank
  and keeps it there for all its turns, in every step, so a conversation
  finds its own prefix in that rank's cache; the real-AIPerf test now
  measures two ranks and fails if a session moves.
- **LMCache hits were not counted as cached on vLLM before 0.16.** There
  the share of prompt tokens from the cache came from the local prefix
  cache alone; what LMCache loaded is a counter of its own,
  `vllm:external_prefix_cache_hits_total`, and is now added. From 0.16 on,
  `vllm:prompt_tokens_cached_total` holds both already (vLLM's
  `PromptTokenStats`); the sites run 0.23 to 0.30, so their results do not
  change.
- **A site whose scheduler is down answered 500, and the entry route did
  not try another.** AI gateway 1.2.0 ignores the pool's `FailOpen`. The
  entry routes now retry on 500 too, next to connect failure, reset and 503.
- **Ready counts after a KServe error.** KServe copies a deployment's ready
  count into the LLMInferenceService only when the rest of its reconcile
  succeeds, and bumps `observedGeneration` anyway, so the copy could be old
  with nothing to say so. The hub now reads the count from the
  `Deployment` or `LeaderWorkerSet` itself, and the desired count from
  there too, which an autoscaler sets when the service has no replicas of
  its own. `serving.kserve.io/stop` is read in any case, as KServe does.
- **A quota on a model the tenant may not call** was accepted, and never
  used: the gateway refuses the model first (403). It is now refused (409),
  and so is a list of models that leaves out a model the tenant has a quota
  on. **Add a quota for…** shows such models as "not in its models", and
  **Models** keeps a model with a quota ticked. The usage of a budget is no
  longer listed for models the tenant may not call.
- **The refusal to drain a model's last site named neither.** It read "No
  other site has capacity for , so draining  would leave the model
  unreachable." It now names the model and the cluster.
- **The planner counted quotas a budget holds in their place.** A tenant
  from before 0.25.0 can have own quotas beside a budget across models. On a
  model with prices the budget holds such a tenant and the quota is not
  enforced, as the Usage page shows, but the planner and the Capacity page
  counted the quota as given: on the sandbox three quotas of 4,294,967,295 a
  day made one model's given 21.5 billion credits. They are left out now.
- **The hub was not upgraded after a merge whose tests were skipped.** The
  `deploy` job of CI had no status check of its own, so it took the skipped
  tests (0.28.0's "tested once") as not successful and was skipped too: the
  merges of 0.28.0 and 0.29.0 built their images but left the sandbox hub on
  0.27.0. `deploy` and `release` now follow the `image` job.
- **The price comparison table** had its first and last columns against the
  box's border. **Selects** had their arrow against the right border; it is
  now drawn inside the padding, in the theme's colours.
- **Documentation.** The AI gateway version quotas by amount and budgets
  across models need (1.2.0, not 1.1.0); that a ClientTrafficPolicy can
  remove headers by prefix; which Envoy version removes token headers on
  every request (1.40.0, not 1.38); what the hub writes outside the gateway
  namespace; what KServe's default scheduler does with best-effort; that the
  pool's `FailOpen` is no safety net; the flow-control example
  (`concurrency-detector`, and agent-router#2595 first); the hub-down,
  usage and label errors of the platform page; the deployment settings
  `tokens.*` and `capacity.*`; the order of sites, which Envoy's Maglev
  does not take from the list.

## Added

- **The tenant as the scheduler's flow.** A token now gives the serving
  site's scheduler the tenant, in `x-llm-d-inference-fairness-id`, written
  from the token's `sub` and replacing what a client sent. With flow control
  on, the scheduler shares each class out by it, so one tenant cannot crowd
  out the others of its class, best-effort or standard, on the entry site
  and on the others. A request with a plain API key has none and joins the
  scheduler's default flow.
- **Warnings when best-effort would not rank below regular tenants.** Each
  sync now says so in the task message, for a pool that serves a
  best-effort model, when:
  - the `LLMInferenceService` behind it runs its scheduler without flow
    control: best-effort requests are then refused only once the scheduler
    counts the pool full, which with its default detector it did not do in
    the lab test of the optimization guide;
  - the site's own class `standard` for it ranks with or below
    `best-effort`, or below 0;
  - the class `best-effort` is for another pool of the same namespace: a
    scheduler takes only the classes that name its own pool (llm-d router
    v0.10.0), so best-effort requests there have priority 0, as regular
    tenants' do.
- **Warnings in the sync.** When a `SecurityPolicy` on a route of the client
  listener replaces the hub's there, Envoy Gateway reports the hub's policy
  `Overridden`. The task message now says so and names the routes: requests
  there are charged to no tenant's budget or quota. It is a warning, not a
  rejection, since the route is the site's. A route that forwards nothing
  (no backend, no mirror) reaches no model and is left out: the gateway
  chart's health check `envoy-ai-gateway-health`, which answers
  `/healthz/gateway` itself with a policy that lets everyone in, overrides
  the hub's policy wherever a site turns it on (`health.enabled`, for a
  global load balancer), and was warned about on every sync until the hub
  read the route.
- **A warning in discovery** when KServe put an LLMInferenceService's route
  on the client listener (`status.router.gateways[].listeners`): requests
  there skip the entry route, the budgets and the quotas.
- **The self-test names the AI gateway version** when a request is not
  counted for the tenant of its token: before 1.2.0 a rule that counts per
  tenant charges one shared bucket.
