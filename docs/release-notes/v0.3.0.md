# 0.3.0 (2026-10-08)

Fixes three ways an update could lose data, and adds three gateway features
found in a review of the Envoy AI Gateway (Agent Router) 1.2 feature set.

## Fixes

- **Cluster update no longer removes the gateway URL.** A `PUT
  /clusters/{id}` without `gateway_url` used to clear it, and discovery then
  fell back to scanning one namespace without any error. A field that is left
  out now keeps its stored value. The same applied to `auth_enabled`, which
  switched API key enforcement off, and to `site`. To remove the URL, send
  `"gateway_url": ""`.
- **Model update no longer removes manual endpoints.** A `PUT /models/{id}`
  without `endpoints` used to delete them. Leaving the field out now keeps
  them, and `"endpoints": []` removes them. `default_limit` and
  `default_window` were reset to 1 token per day the same way and are now
  kept too.
- **A QuotaPolicy is never rendered with an invalid duration or limit.** The
  CRD rejects these, which fails the sync or the controller's finalizer
  update. A tenant quota with such a value is left out of the policy, and a
  default bucket falls back to 1 token per day. The database and the API
  already reject these values, so this is a second line of defence.

## New

- **Cost expression per model.** A model can weight token types differently
  when a request is charged to quotas, for example
  `input_tokens + output_tokens * 4u`. Set it on the model form or as
  `cost_expression` in the API. Rendered as `costExpression` in the
  `QuotaPolicy`.
- **Dry-run quotas.** A tenant quota can count usage without rejecting
  requests. Tick **Dry run** when setting the quota, and press **Enforce**
  when ready. In the API this is `shadow`. Rendered as `shadowMode: true`.
- **Periodic sync.** Every cluster is synced again every 5 minutes even when
  nothing changed. This retries a cluster whose last sync failed and puts
  back objects edited or deleted by hand. Until now a sync only ran after a
  change or on the Sync button. Chart value `config.syncInterval`,
  environment variable `SYNC_INTERVAL`, `0` turns it off.

## Changed behaviour

- `PUT /clusters/{id}` and `PUT /models/{id}` now treat a missing field as
  "keep". A client that relied on leaving a field out to clear it must send
  the empty value instead.
- An explicit `"default_limit": 0` is rejected with a 400. It used to be
  turned into 1.
- A hand-edited managed object is now reverted within `config.syncInterval`.

## Upgrade

Migration `004_cost_and_shadow.sql` adds `models.cost_expression` and
`quotas.shadow`. It runs on startup and needs no action.

## Not verified on a real gateway

- How a dry-run quota interacts with the pool for tenants without a quota.
  The gateway documents that a shadowed rule never rejects, but not whether
  the tenant is then held to that pool, which is 1 token by default. Test
  this on one tenant before relying on it.
- That the gateway accepts every cost expression the API lets through. The
  API only checks the names and characters used.
